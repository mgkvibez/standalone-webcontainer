# ADR-0016: Terminal installs use a volatile offline dependency overlay

**Status:** Accepted by owner authorization, 2026-11-05. Implemented in P1c.

## Decision

The browser terminal supports `npm install` and `npm ci` only against the verified, bundled package corpus. It does not
fetch package metadata or tarballs from the network. The terminal refuses package arguments and unsupported flags.

Project files remain owned and persisted by the page's `ProjectStore`. The installer stages package files in memory;
after a successful install, `package-lock.json` is persisted in the project and package files are published to a volatile
overlay. Runtime snapshots combine the overlay with the page's files. Reloading loses the overlay, and `npm ci` rebuilds
it from the lockfile and bundled corpus. A project switch drops the active overlay. Failed installs do not replace the
previously installed tree.

## Rationale

This reuses the tested resolver, lockfile writer and integrity verifier while keeping project source persistence under
one owner. It also keeps `node_modules` out of `localStorage` and preserves the disposable Worker lifecycle. Persisting a
Worker supervisor, arbitrary registry access, and preview/server lifecycle are separate decisions and remain out of this
change.

## Consequences

- The UI demonstrates the install pipeline and Node module resolution over a synthetic corpus; it does not establish
  public npm compatibility.
- A lockfile can describe packages the bundled corpus cannot serve. Reinstall then fails explicitly until the corpus
  contains those exact package artifacts.
- Package files are not visible in the project explorer and disappear when the page reloads or project changes.
