# ADR-0025: Node's HTTP client is not provided, and the runtime says so

**Status:** accepted, 2026-11-12
**Supersedes:** nothing. **Relates to:** ADR-0002 (API target, Node 20 LTS), ADR-0004 (deliberate gaps), ADR-0020 (preview
gateway), ADR-0023 (the refusal contract this reuses).

> Numbering note: `ADR-0024` is reserved by the parked dev-server reload branch (`docs/reload-needs-invalidation`), which is
> not merged. This record takes 0025 and does not touch that one.

## Context

`http` exists here for the **server** half: user code can `require("http")`, call `createServer`, bind a port into the
registry and be reached through the preview gateway. The **client** half was never implemented, and it was never refused
either. It was simply absent.

The expert audit named that pattern the worst available option, and named it twice (`§6`, `§14 P2`):

> Outbound HTTP: `http.get`/`request` over the existing fetch-based egress, or an explicit ADR that says Node's client is
> not provided and every dependency must use `fetch`. **Today the absence is silent, which is the worst of the three
> options.**

Three options exist and silence is the third: implement it, refuse it by name, or say nothing. Silence fails in a way the
other two do not, because `http.get(url)` produced `TypeError: http.get is not a function`. That reads as a broken runtime,
sends a dependency author looking for a runtime bug, and gives them nothing to change on their side. A named refusal is a
boundary: it says what cannot happen, why, and what to do instead.

The second half of the audit's sentence matters too: "over the existing fetch-based egress". **There is no egress to wrap.**
A program's `fetch` is the browser's own, un-intercepted, and no module in `src/network/` sits under it for outbound
traffic: the service worker and bridge exist to serve previews *into* the runtime, not to carry requests *out*. A wrapper
over `fetch` would therefore not be "the existing egress"; it would be a second, thinner client with a different contract,
presented under Node's name.

## Decision

**1. `http.request`, `http.get`, `http.Agent` and `http.ClientRequest` refuse by name, with a code and a way forward.**

Each throws a `TypeError`-shaped `Error` carrying `code = "ERR_NOT_SUPPORTED"` whose message states the boundary
(`there are no sockets`), the alternative (`the global fetch()`, with CORS semantics, no agent, WHATWG streams) and the ADR.
Refusing rather than omitting is the whole point: the name exists, so a caller reaches the message instead of a
`TypeError` about the name having no function.

**2. `Agent` and `ClientRequest` are classes that refuse in their constructors, not absent names.**

`new Agent({ keepAlive: true })` is how a library configures a client. An inert object returned from that constructor would
be worse than a throw: it would let the configuration appear to have been applied. Constructors are the honest place to fail.

**3. `validateHeaderName`, `validateHeaderValue` and `maxHeaderSize` are IMPLEMENTED, because they are pure.**

Nothing about these needs a socket. They are token and character checks plus the constant `16384`, libraries call them to
fail early, and a refusal would break code that works. `validateHeaderValue` refuses a control character specifically
because a newline in a value is header injection, and a validator that let it through would be worse than no validator. The
error codes are Node's (`ERR_INVALID_HTTP_TOKEN`, `ERR_HTTP_INVALID_HEADER_VALUE`, `ERR_INVALID_CHAR`) because callers
branch on `code`, not on prose.

**4. Every dependency must use `fetch`, and the difference is a documented boundary rather than a gap to be closed later.**

`fetch` is CORS-governed. It has no sockets, no keep-alive agent, no `Expect: 100-continue`, and it streams `ReadableStream`
rather than `stream.Readable`. A package that needs any of those cannot be served here, and pretending otherwise with a
wrapper over `fetch` would move the failure somewhere harder to read. `https.request` already refuses in the same shape
(there is no TLS stack); this ADR makes `http` consistent with it instead of leaving one side silent and the other loud.

**5. This is a boundary, not a defect list entry, and it is recorded as such.**

If a later phase grows a real egress (ADR-0019's runtime origin is the plausible place), this record is what a future
implementer supersedes: the refusal becomes a thin \`http.request\` over that egress, and the reasons above are the shape it
has to satisfy. Until then, silence is not the alternative. This is.

## Consequences

- A dependency that reaches for `http.get` fails **once, loudly, and identifiably**, with `ERR_NOT_SUPPORTED` and a fix in
  the message, instead of failing as a missing function.
- `require("http")` remains useful: the server half, `METHODS`, `STATUS_CODES` and the validators all work.
- A program that only validates headers gets the truth and keeps working; `express`-style code that validates before
  handing off is unaffected by the client refusal until it actually sends.
- The refusal is deliberately **not** a differential case. Node succeeds at `http.get`, so a case would be a permanent
  deviation in a table whose value depends on a deviation meaning something. It is pinned in
  `tests/unit/shims.http-client.test.ts` instead, including one end-to-end run through the loader and the facade so the
  message a dependency sees is the one this ADR describes.
- The audit's §6 row for "Outbound HTTP client" changes from *silent absence* to *refused by name, with an ADR*, which is
  one of the two outcomes it asked for.

## Evidence

- `src/shims/http.ts` — the refusals, `Agent`, `ClientRequest`, `maxHeaderSize`, `validateHeaderName`, `validateHeaderValue`.
- `src/runtime/in-process.ts` — the facade wires all seven, so `require("http")` sees them.
- `tests/unit/shims.http-client.test.ts` — 9 tests: the message carries code, reason, alternative and ADR; `Agent`/`ClientRequest`
  refuse; the server half is untouched; the validators accept a token and refuse a bad name, an undefined value and a control
  character; and user code through the loader gets the refusal rather than a missing function.
- `tools/differential/api-cases.ts` — `http-validate-headers`, which must MATCH real Node (it does: 29/29).
