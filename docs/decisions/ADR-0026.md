# ADR-0026: The filesystem stays a tree, and links are refused by name

**Status:** accepted, 2026-11-12
**Supersedes:** nothing. **Relates to:** ADR-0002 #1 (flat map, derived directories), ADR-0025 (the same refusal shape for
the HTTP client), ADR-0004 (deliberate gaps).

## Context

The audit lists two rows against the incumbent and both are honest about the same absence:

> **Symlinks** — StackBlitz: Yes. Here: No. **Behind.**

and, in its P2 block:

> symlink model in the VFS (ADR), and `utimes`/timestamp setters, before `symlinkSync`/`readlinkSync`/`utimesSync` can exist.

The P0 work had already added `lstatSync` as a documented alias of `statSync` "because no symlinks exist", which was true and
still is. What was missing is the **decision**: whether that stays true, and what a program is told when it asks for a link.

Two things make this a decision rather than a patch.

**A link layer is not a method, it is a change to every lookup.** This VFS is a flat `Map<string, Node>` with directories
derived from the keys beneath them (ADR-0002 #1). A symlink means a path can name another path, so every operation that
takes a path has to resolve a chain first: `stat` versus `lstat`, a hop limit with `ELOOP`, dangling links (Node happily
creates a link to nothing), links to directories (which changes `readdir`, `#existsAsDir`, recursive `rm` and `cp`), relative
targets resolved against the link's own directory, and `realpath`. Half of that implemented is worse than none of it,
because the half that exists looks like support.

**Nothing in this runtime creates links yet.** `npm install` is out of scope for this milestone (ADR-0016, ADR-0004 D-4), the
corpus lane installs from committed tarballs, and no fixture produces one. The place links will first matter is real npm on
POSIX, whose `node_modules/.bin/*` entries are symlinks — and that is also the moment `jsh`-style shebang shims become a
requirement, which is a separate subsystem.

## Decision

**1. The VFS remains a tree. `symlinkSync`, `linkSync` and `readlinkSync` refuse by name.**

Each throws with `code = "ERR_NOT_SUPPORTED"` and a message that states the boundary (a name cannot point at another name),
the alternatives a caller can act on today (`fs.copyFileSync` for content, or the real path), and this ADR. This is the same
shape as ADR-0025's HTTP refusal and for the same reason: the audit's own words, "the absence is silent, which is the worst
of the three options". `fs.symlinkSync is not a function` reads as a broken runtime; `ERR_NOT_SUPPORTED` with a reason reads
as a boundary, which is what it is.

**2. Hard links are refused in the same place, and the reason is different enough to write down.**

`linkSync` is not a symlink, but it cannot exist here for a reason of its own: a hard link means two names for one inode, so
`unlink` becomes "decrement a link count" and a node needs a count field plus rules for when the bytes are actually freed.
This VFS has one name per node by construction, and its `unlink` deletes the entry. Saying "no links" while quietly
implying hard links exist would be the kind of half-truth this project has been avoiding.

**3. `lstat`, `lutimes` and `realpath` stay as documented aliases, and each says why.**

With no link layer, `lstat` and `stat` cannot differ, `lutimes` and `utimes` cannot differ, and `realpath` has nothing to
resolve beyond normalisation. They are present, correct, and **documented at the definition** rather than silently aliased,
so the next reader does not have to work out whether the alias is an oversight. `isSymbolicLink()` answers `false` for the
same reason.

**4. Timestamps become settable, because that half of the audit's sentence needs no model.**

`utimesSync`, `utimes`, `lutimes`, `lutimesSync` and `fs.promises.utimes` are real: the VFS stores `modifiedAt`, so setting
it is a write to a field, not a design. Node takes **seconds**, the VFS stores **milliseconds**, and one helper does that
conversion because getting it wrong is silent (every file in 1970, no error). `atime` is accepted and not stored: this VFS
has no access-time accounting, and adding it would turn every read into a write to the node.

**5. A directory that is derived gains an entry when its time is set.**

`mkdirSync` already materialises parents it creates; `utimesSync` does the same, because the alternative is a call that
reports success while `stat` still returns epoch timestamps. The root is the exception and throws with a reason: it is not a
keyed entry, and inventing one would put a node at `/` that every `readdir` and descendant count has to special-case.

**6. What would reopen this.**

A real npm install on POSIX, or pnpm (whose store is links all the way down), or a workspace layout with `npm link`. Any of
those makes the link layer load-bearing rather than optional, and the design above is what that work has to satisfy. The
trigger is written here so that a future reader does not have to reconstruct the argument from a chat log: when
`node_modules/.bin` has to work, implement resolution as one resolver in front of every path, with a hop limit and `lstat`
divergence, and supersede this record.

## Consequences

- A dependency that asks for a link fails **once, loudly and identifiably**, with a code and a fix in the message.
- `require("fs")` remains honest: the surface that exists does what it says, and the surface that does not exist says so
  instead of failing as a missing function.
- `fs.utimesSync` works, including on files, explicit directories, and derived directories; the root refuses with a reason.
- The audit's §6 "Symlinks" row changes from *silent absence* to *refused by name, with an ADR* — the same remediation its own
  P2 block asks for, and the same one ADR-0025 applied to HTTP.
- The link refusals are **not** differential cases: Node creates links, so a case would be a permanent deviation. They are
  pinned in `tests/unit/shims.fs-links.test.ts`, and `utimes` **is** a differential case, because both runtimes answer it and
  must agree.

## Evidence

- `src/shims/fs.ts` — `refuseLink`, `secondsToMilliseconds`, `utimesSync`/`lutimesSync`, `symlinkSync`/`linkSync`/`readlinkSync`,
  the callback forms derived from the promise members, and `promises.utimes`/`symlink`/`link`/`readlink`.
- `src/vfs/index.ts` — `utimesSync(path, modifiedAt)`, including the derived-directory materialisation and the root refusal.
- `src/vfs/port.ts` — `utimesSync` as an **optional** capability, so a substrate without stored timestamps says so instead of
  pretending, the same pattern as `statManySync`.
- `asCallback` now defers through `Promise.resolve().then(...)`, so a synchronous throw inside a derived operation reaches the
  callback instead of escaping a function that promises to call back. That was a latent bug for every derived member; the
  refusals are what made it reachable.
- `tests/unit/shims.fs-links.test.ts` — the refusals' code/message/alternative, the aliases agreeing, and `utimes` across
  files, explicit directories and derived directories.
